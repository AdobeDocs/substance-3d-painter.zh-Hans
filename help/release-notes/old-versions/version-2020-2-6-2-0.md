# 版本2020.2 (6.2.0)

**Substance Painter2020.2.0 (6.2.0)**&#x200B;引入了新的UV图块工作流程，允许跨UDIM绘画。 它还包括针对任何类型项目的几项性能和项目大小改进。

发行日期：*2020年7月23日*

&#x200B;>> 

艺术家来源：[Damien Guimoneau](https://www.artstation.com/damz)创作的“龙”，以及[Jason Huang](https://www.artstation.com/jasonhuang)创作的“机器人”。

## 主要功能

### 跨UDIM绘画的全新UV拼贴工作流程

![](../../assets/banner-uvtiles.jpg)

在此版本中，我们将新的UV拼贴工作流程引入到Substance Painter中，以允许在UDIM拼贴上进行绘制。

使用新工作流程，**UV不再拆分为单独的纹理集**。 相反，根据网格的材质分配，UV拼贴包含在单个纹理集内。 在2D和3D视口中，同一“纹理集”中的UV拼贴可以&#x200B;**涂抹过去，而不会出现接缝**。

UV磁贴是以通用方式描述此新工作流的术语，因为UDIM主要是命名约定。 虽然UDIM是目前唯一可用的约定，但我们计划在未来将其扩展（例如支持Mudbox或ZBrush命名）。 我们还考虑用负坐标来支撑拼贴，这在UDIM格式中是不可能的。 这就是我们为此工作流程选择更广义的术语的原因。

下面概述了这一新工作流程中引入的更改：

* **正在创建UV磁贴项目**\
  创建新项目时，有一个新设置可用于指定是否应使用新工作流。

  请注意，一旦确定了工作流程并创建了项目，以后就不能再与其他设置相反对其进行更改。

  ![](../../assets/new-project-setting.png)
* 2D视区中的UV拼贴

  在使用新的UV磁贴工作流程时，2D视图现在将显示一个新网格，其中每个UV磁贴都有一个专用的UDIM编号。 可以单独绘制每个拼贴。

  ![](../../assets/paint-2d-view.jpg)
* 在UV磁贴上绘画

  UV 平铺

  位于同一纹理集中的纹理可以无缝跨对象绘制。 这样，只需将UV磁贴数量相乘，即可提高资源的总体分辨率和质量。
* “纹理集列表”窗口中的UV拼贴

  该

  纹理集列表包含

  已更新，以列出与导入的网格上找到的材质相关的UV拼贴。 每个UV磁贴都根据UDIM约定显示其名称。

  ![](../../assets/uv-tiles-texture-set-list.png)
* 更改每个UV图块的分辨率

  虽然每个UV拼贴的默认分辨率基于其父纹理集，但可以按拼贴覆盖它。 只需选择“纹理集列表”中的拼贴，然后转到“纹理集设置”窗口即可更改分辨率。 当拼贴的分辨率被覆盖时，新的分辨率将显示在2D视图中的编号旁边。

  ![](../../assets/override-resolution-uv-tiles.gif)
* 新建图层栈栈图标

  图层栈叠具有绘画图层和填充图层的新图标。 由于UV拼贴具有多套纹理，因此无法在此小区域中显示所有纹理。 这有助于提高性能，因为不再需要计算特定的缩略图。 这组新图标可用于常规项目，也可在主要设置中启用设置（请参阅下文）。

  ![](../../assets/layer-stack-icons.png)
* 在图层上新建UV磁贴蒙版

  UV拼贴蒙版是一种用于遮蔽入点/出点图层的新方式，比常规蒙版更高效。 由于它允许完全放弃特定UV磁贴的计算，因此提供了更好的性能。 我们建议使用此工具在处理包含许多UV磁贴的项目时获得舒适的体验。 有关详细信息，请参阅文档中的[专用页面](../../interface/layer-stack/geometry-mask.md)。

  ![](../../assets/uv-tile-mask-3d-edition.gif){width="550px"}
* **通过蒙版UV磁贴绘画**\
  当多个UV拼贴位于同一纹理集中时，可能很难绘制网格的某些区域，因为几何图形的其他部分挡住了道路。 为了避免这种情况，在名为&#x200B;**绘画描边忽略蒙版UV拼贴**&#x200B;的上下文工具栏中添加了一个新的绘画设置。 启用此设置后，通过UV拼贴蒙版排除的任何UV拼贴都将在视口中隐藏，从而允许绘画描边穿过/忽略它们。 修改UV拼贴蒙版将重新计算画笔描边，因为它允许重新导入可能已修改的UV拼贴或需要排除的新几何形状的网格。 这样可以避免重做绘画描边。

  ![](../../assets/paint-through-tooltip.png)

  ![](../../assets/paint-through.gif)
* 烘焙UV磁贴

  烘焙器还支持UV磁贴，烘焙窗口中现在有一个选择列表

  以指定应烘焙的拼贴和纹理集。 通过单击并拖动复选框或使用新的下拉菜单，可以快速更改选择。

  ![](../../assets/baking-window-uv-tiles.png)

  ![](../../assets/baking-menu.png)
* 使用新的$udim标签导出UV拼贴纹理

  输出模板中添加了一个新标签，允许导出文件名中包含UV磁贴编号的文件。 目前只有UDIM公约可用。 当标签不可用时，也可以使用括号来定义文件名中的可选元素。 例如，这样可创建仅在UV拼贴项目可用时附加UDIM编号的文件名，从而使导出预设与任何类型的项目兼容。

  ![](../../assets/udim-tag.png)
* **导入图像序列**&#x200B;图像序列是一系列纹理，其中每个都与特定的UV图块匹配。 要导入图像序列，只需将该序列的第一个文件拖放到架中或使用导入资源窗口。 序列中的其余文件也将自动导入。 这些序列将作为单个资源显示在搁板中，并带有指示它们包含的文件数量的数字。 要使用序列，只需将其拖放到填充图层中即可。 投影模式将自动设置为&#x200B;**填充（每UV图块匹配）**。

  ![](../../assets/image-sequence-shelf.jpg){width="600px"}

  ![](../../assets/fill-projection-mode-uv-tiles.png)
* 支持具有类似网格的小平面

  Alembic Faceset现在作为要拆分为纹理集的材质导入。 此更改使Alembic网格与新的UV拼贴工作流程兼容。 如果Alembic网格包含不在小平面中的表面，这些表面将自动放入名为DefaultMaterial的纹理集中。

要了解有关新UV磁贴工作流程的更多详细信息，请查看[专用文档](../../features/uv-tiles/uv-tiles.md)。

>

### 新暂停引擎

![](../../assets/banner-pause-engine.jpg)

现在可以在工作时暂停Substance Painter引擎。 引擎暂停后，将注册所有纹理计算、视口更新或绘画描边，但不会计算它们。

这个新动作允许设置和调整复杂图层栈叠，并将计算延迟到最后一刻。 暂停引擎的主要优点是避免中间计算，而只计算最终结果。 这样可使应用程序响应速度更快，整体更新速度更快。 要权衡的是，在引擎停止工作之前，不会出现视觉反馈。

要暂停引擎，只需单击视口上方上下文工具栏&#x200B;**中的**&#x200B;按钮，或使用&#x200B;**快捷键Shift + Escape**（可在“设置”中修改）。 要取消暂停引擎，请关闭按钮或重复使用快捷键。

![](../../assets/pause-animation.gif)

### 性能改进

![](../../assets/banner-performances.jpg)

* **纹理导出速度更快**\
  导出纹理的速度应显着加快，尤其是对于生成许多纹理的繁重项目。 在生成和写入纹理的方式上进行了一些改进。 在对包含许多纹理集或复杂图层栈叠的项目进行内部测试时，我们发现导出过程通常会加快&#x200B;**4或5倍**。
* **打开项目时缓存计算延迟** Substance Painter使用缓存系统以允许快速调整和混合图层。 在以前的版本中，每次打开项目时都会计算此缓存（通过视区底部的绿色加载栏可见）。 现在，缓存计算仅在尝试编辑图层（例如，通过绘制或微调填充图层参数）时触发。 此更改允许打开项目，而无需在开始工作之前等待并切换到所需的纹理集。 计算也更为精细，仅计算所需的内容。 例如，对于包含UV拼贴的项目，将只计算需要修改的拼贴。
* **网格图异步加载**&#x200B;网格图现在异步加载。 这意味着在等待加载网格映射时，应用程序将不再被阻止。 在视区中显示网格贴图时，这一点特别明显（如下图所示）。 这也使项目打开速度更快，因为不再等待网格图。

  ![](../../assets/meshmaps-loading.gif)
* **改进了蒙版视图模式编辑**\
  当按住ALT键并单击蒙版（或专用视图模式）以在视口中显示它时，现在只对蒙版执行纹理更新。 这意味着使用此视图模式时，绘画和编辑效果会更加流畅，因为任何其他计算都会延迟到视区设置回材质模式为止。

  ![](../../assets/mask-view-mode.png)
* **新建图层栈栈缩略图**\
  如前所述，图层栈栈现在可以使用一组新的图标。 使用这些图标可以提高常规性能，因为无需计算缩览图。 虽然这对于UV磁贴项目是自动的，但常规项目也可以选择使用这些图标，方法是转到&#x200B;**编辑>设置**&#x200B;并启用&#x200B;**将图层栈叠缩略图替换为图标**。

  ![](../../assets/icon-setting.png)
* **更快的增量保存**&#x200B;由于项目可以更小，并且保存过程对于更改的数据更精细，因此增量保存（按CTRL+S）现在要快得多。 这在大型项目中尤其明显。
* **改进了Iray启动性能**\
  使用Iray切换至渲染模式应更快一些，因为我们改进了管理应用程序内共享内存的方式。

### 项目大小改进

![](../../assets/banner-filefootprint.png)

项目文件以[占用大量文件](../../technical-support/workflow-issues/project-issues/projects-are-really-big.md)而闻名。 我们花了一些时间调查问题的根源，并设计了一些解决方案。 此版本引入了第一组更改：

* **将面包机输出切换到灰度图像**\
  在之前的版本中，任何情况下烘焙师都会输出RGB图像。 现在，灰度烘焙器（曲率、环境遮蔽）将仅输出灰度图像。 这一简单的更改可以将项目大小从20%减少到60%。 要利用此更改，需要重新生成现有项目中的网格图。
* **更改烘焙师的默认扩散和膨胀设置**\
  以前，烘焙器将生成1个像素的扩展，然后生成扩散图案（UV 岛外部的模糊像素）。 由于渐变很难压缩，因此此设置会生成非常沉重的纹理。 因此，已更改默认设置以减少该问题。 默认情况下，“扩散”现在处于关闭状态，并且扩展已设置为32像素（应该与4K分辨率匹配）。 我们建议将现有项目切换到这些新设置并返工，以利用这项改进。

  ![](../../assets/baking-menu_1.png)

  ![](../../assets/baking-menu-list.png)

  通过对“纹理集”列表进行重新处理以包含UV磁贴，进行了一些细微的更改以使UI不那么杂乱。 以前允许创建和切换到不同着色器实例的功能现在已移入“纹理集”设置。
