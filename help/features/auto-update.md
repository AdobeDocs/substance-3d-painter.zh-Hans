# 自动资源更新

![](../assets/banner_autoupdate.jpg)

自动资源更新（或<b>自动更新</b>）是[资源窗口](../interface/assets/assets.md)的一项功能，可用于在新版本可用时重新加载和更新资源。 此过程可在界面中自动或手动触发，也可通过Python脚本触发。

![](../assets/auto_update_menu.png)

## 教程

您可以观看快速教程，大致了解此功能：

## 启用自动更新

![](../assets/auto_update_red_icon.png)

要启用<b>自动更新</b>，只需转到“资源”窗口底部，然后单击双箭头图标。 这将打开自动更新菜单及其所有设置。 然后，启用<b>自动更新</b>部分下的可用选项之一。

### 自动更新

![](../assets/auto-update_auto_settings.png)

自动更新设置控制应用程序查找更新的频率以及查找更新的位置。

| 设置 | 描述 |
| --- | --- |
| <b>资源面板</b> | 如果启用，自动更新将在当前加载的所有库中查找要更新的资源。 其中包括当前项目。 但是，它不会更新在图层栈栈、显示设置、着色器设置等中使用的资源。 |
| <b>项目中使用的资源</b> | 如果启用，自动更新将查找当前项目当前导入和使用的要更新的资源。 这适用于在图层栈栈、显示设置、着色器设置等中使用的资源。 |
| <b>每x分钟更新一次</b> | 控制应用程序查找资源更新的频率。 0分钟的延迟将每隔几秒触发一次更新。 请注意，这种低延迟会导致性能问题。 |

>[!NOTE]
>
> 如果启用自动更新，则应用程序将在每次重新获得焦点时自动查找更改。

### 手动更新

![](../assets/auto-update_manual.png)

手动更新操作是一种在需要时触发更新系统的便捷方法。 无论是否启用自动更新设置，都可以使用它们。

| 设置 | 描述 |
| --- | --- |
| <b>更新资源面板</b> | 启动自动更新过程。 行为方式与<b>资源面板</b>设置相同（请参阅上文）。 |
| <b>更新项目中使用的资源</b> | 启动自动更新过程。 行为方式与项目</b>中使用的<b>资源相同（请参阅上文）。 |

## 高级设置

![](../assets/auto-update_mismatch.png)

使用高级设置可以控制更新过程的行为。

| 设置 | 描述 |
| --- | --- |
| <b>当资源参数不匹配时跳过资源</b> | 如果启用，当新版本与旧版本不匹配时，自动更新过程将避免更新资源。 例如，如果Substance素材包含新版本中不再存在的参数（因为它们已被移除或重命名），则更新过程将忽略该资源并保留旧版本。 |

>[!NOTE]
>
> 要强制更新不匹配的资源，您可以禁用<b>当资源参数不匹配时跳过资源</b>设置。

## 更新状态和日志

![](../assets/auto-update_log.png)

更新资源后（自动或手动），该过程的结果将显示在<b>日志</b>窗口的<b>资源</b>选项卡中，报告成功的更新和问题。 如果资源不匹配（请参阅上文），请根据资源提供问题的详细信息。

通过单击自动更新菜单右上角的专用图标，可以快速打开日志：

![](../assets/auto_update_log_icon.png)

>[!NOTE]
>
> 更新后出现一个或多个问题时，日志图标会显示一个小警告图标。

根据更新过程的不同，可能会出现几种类型的问题：

| 问题 | 描述 |
| --- | --- |
| <b>无法在“资源”面板中更新</b> | 此消息表示出现了一个问题，导致更新系统无法继续。 展开资源名称以获取更多信息。 |
| <b>(filename)。(format)不存在。 无法重新加载（资源名称）</b> | 此消息表示无法再找到资源的源文件（因为它已被移动或删除）。 一个简单的修复方法是（通过右键单击菜单）在“资源”窗口中重新导入资源或重新定位资源。 |

## 旧项目消息

![](../assets/auto_update_old_project_dialog.png.img.png)

打开旧项目时，弹出消息警告中会提供一个选项，用于通知自动更新过程。 这是快速禁用自动更新流程的便捷方法，以防在打开旧项目之前它仍处于启用状态。
